# OttoRestart — архитектура изолированного интерфейса и план разработки

**Проект:** `otto-bot`  
**Модуль:** `OttoRestart`  
**Назначение:** управление процессом Restart 3/12M для OTTO Market  
**Редакция:** v1.0, 12.10.2026  
**Статус:** техническое задание и план; не означает, что изменения уже внесены в SSH-репозиторий.

> [!IMPORTANT]
> **Неприкосновенное правило: OttoFlow не изменять.** Ни существующие страницы, компоненты, Sidebar, маршруты, API, модели, сервисы, задачи, настройки, стили, поведение, ни схемы данных, от которых зависит OttoFlow. Разрешено **только читать** код OttoFlow и брать его решения за образец для **новых файлов OttoRestart**. Если реализация требует изменить существующий файл или общую точку входа — **остановиться, объяснить зависимость и запросить отдельное разрешение**; не обходить это правило молча.

## 0. Окончательно утверждённые решения

| Вопрос | Решение |
|---|---|
| Название | **OttoRestart**, не OttoLibrary |
| Расположение | Тот же репозиторий `otto-bot`, но **отдельный интерфейс и отдельный функциональный модуль** |
| OttoFlow | **Read-only**; его поведение и файлы не менять |
| Навигация | Собственная боковая панель, layout, маршруты, Dashboard, UX и настройки OttoRestart |
| Переключение | В OttoRestart переключатель продуктов слева сверху: OttoRestart / OttoFlow. Переход из OttoFlow в OttoRestart через его UI пока **не предусмотрен**, так как для этого пришлось бы изменить OttoFlow |
| URL | Предпочтительно `/restart` и вложенные `/restart/...`; окончательный способ подключения — после read-only аудита маршрутизации |
| Backend | Собственные API, сервисы, состояния, задачи и очередь для Restart; не изменять и не вызывать внутренние мутирующие очереди OttoFlow |
| Старые EAN | Пользователь загружает их отдельным файлом |
| Новые EAN | Пользователь загружает пул отдельным файлом; бот **не генерирует** новые EAN |
| Идентификаторы по умолчанию | `new_ean = new_sku = new_product_reference` — только когда это допустимо для реального нового товара |
| Альтернативный вариант | `new_ean = new_sku`, `new_product_reference = old_product_reference` — отдельный эксперимент для настоящих вариаций, только после проверки правил OTTO |
| Базовая цена | **Текущая стандартная цена старого SKU на OTTO**, отдельно для JV/XL; не Aftercool, не Excel и не `salePrice` |
| Цена JV | `new_standard_price = old_otto.standardPrice.amount − 10.00 EUR` |
| Цена XL | `new_standard_price = old_otto.standardPrice.amount − 15.00 EUR` |
| Старые товары | Не пытаться автоматически удалить, не перезаписывать и не изменять их состояние |
| Начальная стадия | Read-only аудит, проектирование, импорт, Dry-Run. **Никакой реальной публикации до разрешения сценария OTTO/GTIN и одобрения оператора** |

**Отличие от предыдущего плана v3:** рекомендации внедрить `/dashboard/restart`, пункт меню в существующий `Sidebar.tsx` и прямую интеграцию во внутреннюю очередь OttoFlow **отменены**. Это противоречит строгой изоляции.

## 1. Концепция продукта

```text
                      OTTO-mapping-tool (один репозиторий)
                              │
                 ┌────────────┴────────────┐
                 │                         │
          OTTOFLOW (существует)    OTTORESTART (новый)
            БЕЗ ИЗМЕНЕНИЙ          изолированная область
                 │                         │
            старый UI              собственный UI
            старый API             собственный API
            старые задачи          собственные задачи
            старая очередь         собственная очередь
                 │                         │
                 └── общие внешние сервисы ─┘
                     (OTTO / Aftercool / БД)
                     с явными границами доступа
```

Изоляция здесь **логическая и файловая**, а не обязательно два отдельных сервера. Можно использовать существующий хост, авторизацию и инфраструктуру **только через стабильные нейтральные интерфейсы**, если для этого не требуется менять OttoFlow. Нельзя напрямую обращаться к приватным React-store, внутренним мутирующим сервисам или таблицам очереди OttoFlow как к API OttoRestart.

**Общий стиль интерфейса**: OttoRestart визуально родственен OttoFlow (тёмная navy-тема, индиго/фиолетовые акценты, карточки, типографика, таблицы), но это самостоятельный продуктовый интерфейс: с собственной навигацией, состоянием аккаунта, настройками и компонентами. Не импортировать компоненты из OttoFlow напрямую; если нужна аналогичная кнопка/таблица — реализовать её в собственном модуле, ориентируясь на исходник.

### 1.1. Переход между интерфейсами

- Верхний левый угол OttoRestart: логотип, `OttoRestart`, подпись «Restart 3/12M», стрелка раскрытия.
- Меню: `OttoRestart — Управление Restart 3/12M` (выбран) и `OttoFlow — Операции и экспорт` (переход в **уже существующий URL OttoFlow**).
- При возврате OttoRestart по `/restart` сохраняются собственные фильтры/аккаунт в независимом состоянии, если это безопасно и допустимо.
- **Никакой вставки обратного переключателя в OttoFlow.** Ссылка на `/restart` может существовать вне UI OttoFlow (закладка, отдельная стартовая страница — лишь если не требует его изменения).
- Значения JV/XL в OttoRestart не должны менять активный аккаунт в OttoFlow; нельзя полагаться на его глобальный React-store.

## 3. Предлагаемые маршруты OttoRestart

Маршруты показаны как целевой контракт и требуют сверки с фактической структурой Next.js.

| Route | Экран | Назначение |
|---|---|---|
| `/restart` | Обзор | Метрики, состояние партий, EAN-пул, проблемы |
| `/restart/batches` | Партии | Полный список партий с поиском, фильтрами и созданием |
| `/restart/batches/[batchId]` | Детали партии | Таблица товаров + вкладки workflow + массовые действия |
| `/restart/ean-pool` | Пул EAN | Импорт, проверка, свободные/зарезервированные/использованные EAN |
| `/restart/review` | Проверка | Единая очередь товаров, ожидающих проверки/подтверждения |
| `/restart/queue` | Очередь | Собственные Restart-задачи, остановка/возобновление, результаты OTTO |
| `/restart/history` | История | Статусы, события, отчёты, поиск старых/новых EAN |
| `/restart/settings` | Настройки | Правила Restart, лимиты, флаги публикации, диагностическая информация |

Не создавать `/dashboard/restart`: это визуально и концептуально часть OttoFlow, а не самостоятельный интерфейс.

## 4. Дизайн страниц и UX-сценарии

### 4.1. Dashboard — «Обзор Restart»

**Header:** «OttoRestart / Обзор», account switcher `JV | XL`, поиск старого/нового EAN, статус соединения с OTTO и кнопка обновления.

**KPI:**
- Всего кандидатов за выбранный период.
- Готовы к проверке.
- Требуют исправления (цена / данные / GTIN / OTTO).
- В очереди/обрабатываются.
- ONLINE подтверждено (не «POST отправлен»).
- Свободные новые EAN.

**Контент:** последние партии; статусный график; блок «Требуют внимания» с быстрым переходом по фильтру; остаток пула; недавние операции. Все показатели исходят из API, никаких выдуманных чисел в production-UI. Для незагруженных данных предусмотрены `loading`, `empty`, `error`, `retry`.

**Основные действия:** «Создать партию» и «Загрузить новые EAN». Никакой глобальной кнопки «Опубликовать всё» на Dashboard.

### 4.2. Партии — `/restart/batches`

- Таблица партий: ID, имя/файл, JV/XL, 3M/12M, количество строк, прошло валидацию, ошибки, одобрено, статус, дата, создатель.
- Фильтры: аккаунт, период, статус, дата, поисковая строка.
- Действия: создать партию, открыть, скачать отчёт, отменить ещё не отправленные элементы.
- Партии JV и XL **не смешивать по умолчанию**; пользователь может явно менять область поиска, если ему это разрешено.

**Создание партии (wizard/modal):**
1. Выбрать JV/XL и 3M/12M (если их нет в строках).
2. Импортировать `.xlsx`, `.csv` или `.txt` со старыми EAN; желаемый формат — `EAN + title + price`, но достаточно **списка EAN**. Цена в файле только контрольная и никогда не является базой расчёта.
3. Просмотреть Dry-Run: количество записей, дубли, несуществующие/неподтверждённые SKU, расхождения аккаунтов, доступность Aftercool, статус OTTO, получение OTTO standardPrice, дефицит новых EAN.
4. Создать партию только после отдельного подтверждения; Dry-Run не тратит EAN и не отправляет данные в OTTO.

### 4.3. Детали партии — `/restart/batches/[batchId]`

Вместо жёсткого wizard использовать **вкладки-представления одной партии**:

1. **Кандидаты:** импорт, сверка исходных товаров, найденные проблемы.
2. **Подготовка:** резерв EAN, данные и изображения, AI-название/атрибуты, проверка.
3. **Утверждение:** сравнение Old ↔ New, замечания, подтверждение подготовленной версии.
4. **Публикация:** отдельная очередь, ошибки обработки, статусы OTTO, диагностика.
5. **История:** audit событий, попытки, ID процессов, результаты.

Можно открыть вкладку «Публикация» в любой момент, даже когда остальные не завершены. **Возможность просмотра не равна разрешению выполнить действие.** Переходы состояния проверяются сервером.

#### Основная таблица партии

Для нескольких тысяч и более товаров **серверная** пагинация, поиск и фильтры; виртуализация по необходимости. В таблице не более основных колонок:

| Поле | Отображение |
|---|---|
| Выбор | Чекбокс только для доступных операций; явно показывать охват «страница / все отфильтрованные» |
| Товар | Миниатюра, краткое старое/новое название |
| EAN / SKU | `OLD → NEW`, копирование полного значения, поиск |
| Цена OTTO | `standardPrice → −10/−15 € → new standardPrice`, время чтения |
| Качество | Сводка атрибутов/ошибок, причина блокировки |
| OTTO | `activeStatus` и `marketplaceStatus` по отдельности |
| Restart | Шаг обработки, последний ответ, детали |
| Действия | Открыть сравнение, обновить данные, проверить ошибку |

Дополнительные поля через настройку колонок или подробную карточку. Не помещать 11–15 обязательных колонок на один экран.

**Массовая панель:** «Выбрано N / доступно к утверждению M / заблокировано K», «Утвердить допустимые», «Экспорт», «Отправить в очередь» (доступно только после всех разрешений). Действия выполняются на сервере по подтверждённому набору ID, а не по полному массиву строк в браузере.

### 4.4. Drawer — «Старый товар ↔ Новый товар»

Ширина ориентировочно 900–1100 px на широких экранах; на узком экране — полноэкранная карточка. Две колонки одинаковой структуры:

| Поле | Старый товар | Подготавливаемый товар |
|---|---|---|
| EAN | `old_ean` | `new_ean` |
| SKU | `old_sku` | `new_sku` |
| Product Reference | `old_product_reference` | `new_product_reference` + режим |
| Название | Название источника | Проверяемое AI-название, счётчик символов |
| Цена | `old_sku.standardPrice.amount` из OTTO | Рассчитанный `new_standard_price` |
| Статусы | `activeStatus`, `marketplaceStatus` | локальная готовность / фактические статусы OTTO после отправки |
| Категория | Исходная | Проверенная целевая |
| Атрибуты | Имеющиеся | Копируемые/добавленные + дифф |
| Изображения | Источник | Предпросмотр подготовленных |

Внизу: список отличий, результаты валидации, источник и возраст цены, журнал изменений, кнопки «Сохранить изменения», «Обновить из OTTO», «Проверить», «Утвердить» (условно). Статусы и цены **не редактировать вручную как свободный текст**, исключить неявные изменения.

**Режим Product Reference:** `NEW_PRODUCT_REFERENCE` и `REUSE_OLD_PRODUCT_REFERENCE` показываются только в рамках разрешённых правил и соответствующих товарных сценариев; второй режим недоступен для production по умолчанию. Изменение любого существенного поля после утверждения сбрасывает его.

### 4.5. Страница пула новых EAN — `/restart/ean-pool`

Не тесная модалка, а отдельная страница:

- Метрики `AVAILABLE`, `RESERVED`, `SUBMITTED`, `USED`, `QUARANTINED`.
- Импорт `.xlsx/.csv/.txt` отдельным файлом; EAN как строка, сохранение ведущих нулей, проверка контрольной цифры, дублей и прав на GTIN.
- Таблица EAN: номер, статус, источник импорта, резервирующая партия, время, основание блокировки.
- Атомарное резервирование, защита от параллельного использования, просмотр истории.
- Отправленный/сомнительный EAN не возвращать в свободный пул автоматически после таймаута.

### 4.6. Проверка товаров — `/restart/review`

- Единый рабочий список ожидающих ручного решения, **только по доступным пользователю аккаунтам**.
- Отдельные фильтры: ошибка стандартной цены, ошибка EAN/GTIN, отсутствие данных, категория/атрибуты, статус OTTO, изменившаяся цена.
- Подтверждение не является публикацией; кнопка «В очередь» всегда требует отдельной проверки и подтверждения.
- Утверждение привязано к **конкретной версии подготовленного payload и снимку цены**.

### 4.7. Очередь и мониторинг — `/restart/queue`

- Только **собственные задачи OttoRestart**: ожидание, обработка, принятые API, Marketplace ONLINE, ошибки, требуется вмешательство.
- JV/XL отдельными очередями/логическими партициями, учёт суммарных лимитов OTTO с другими клиентами без изменения OttoFlow.
- Просмотр процесса `processUuid`, логов попыток и результата проверки статуса.
- `Pause / Resume / Stop new submissions`; операции не «откатывают» уже отправленные товары.
- При сетевой неопределённости делать reconcile в OTTO до повторного POST; не допускать двойной отправки.

### 4.8. История и отчёты — `/restart/history`

- Поиск по `source_ean`, `new_ean`, SKU, Product Reference, партии, аккаунту, периоду, дате.
- Таймлайн `import → price fetch → reserve → prepare → approve → submit → OTTO processing → ONLINE/error`.
- Выгрузка CSV/XLSX с корректной кодировкой EAN как текста, ценой, скидкой, временем получения цены, статусами, причиной ошибки и процессами.
- Хранить не только последний статус, но и историю изменений и повторных попыток.

## 6. Backend OttoRestart: независимый сервисный контур

Цель — чтобы логика Restart **не зависела от изменения функционирования OttoFlow**.

Предлагаемые компоненты, размещаемые в **новом** namespace:

| Компонент | Ответственность |
|---|---|
| `RestartImportService` | Старые EAN, валидация, идемпотентный импорт |
| `RestartEanPoolService` | Загрузка, проверка и транзакционный резерв новых EAN |
| `RestartSourceAdapter` | Чтение исходных данных Aftercool/открытых нейтральных источников по **старому** EAN |
| `RestartOttoReadClient` | GET старого SKU, `standardPrice`, статусы и диагностические данные нужного аккаунта |
| `RestartPreparationService` | Подготовка карточки, корректный content mapping, AI/валидация |
| `RestartApprovalService` | Утверждение конкретной версии карточки и цены |
| `RestartPublishService` | **Собственная** разрешённая отправка и сверка ответа OTTO |
| `RestartWorker` | Собственная очередь/namespace задач, retry, rate-limit и stop |
| `RestartAuditService` | События и история изменений |
| `RestartReportService` | Экспорт CSV/XLSX |

**Паттерны OttoFlow можно воспроизвести в новых файлах**, но не подключать его внутренние очереди/сервисы с побочными эффектами как скрытую зависимость. Если существующий официальный клиент OTTO вынесен в действительно общий, стабильный инфраструктурный слой (не часть OttoFlow), его можно использовать после проверки контрактов. Иначе собственный адаптер OttoRestart.

### 6.2. Данные и таблицы

Только новые сущности Restart (названия при реализации уточнить по ORM):

- `restart_batches`: `id`, `account`, `period`, исходный файл, статус, настройки, инициатор, timestamps.
- `restart_items`: `batch_id`, `account`, `source_ean`, `old_ean/sku/ref`, `new_ean/sku/ref`, title, category, price snapshot, проверки, статус, ссылки на результаты OTTO.
- `restart_ean_registry`: `ean`, источник, статус, резерв, история, уникальность.
- `restart_events`: события, автор, время, статус до/после, безопасный diff.
- По необходимости `restart_publish_attempts`: отдельные попытки, request keys, task UUID, ответы и результаты reconcile.

Миграции **только добавляют** новые таблицы/индексы, не меняют таблицы, поля, ограничения, существующие миграции или связи OttoFlow. Доступ к общим данным — через read-only адаптер; никакого переписывания `ProductMapping` и `PublishQueueItem` в рамках нового модуля.

### 6.3. Обязательная логика цены

```text
source = OTTO / current account / old SKU
base = GET /v5/products/{old_sku}/prices → standardPrice.amount

if account == JV: discount = 10.00 EUR
if account == XL: discount = 15.00 EUR

new_standard_price = base − discount
```

- `salePrice` не брать за основу, не наследовать старую sale-акцию автоматически.
- Aftercool, Excel/CSV и внутренняя БД не являются fallback ценой.
- Нет цены OTTO / не тот аккаунт / неправильная валюта / некорректная сумма → `PRICE_UNAVAILABLE` или `PRICE_REVIEW_REQUIRED`, **без отправки**.
- Расчёт через `Decimal` или целые центы, не `float`.
- Сохранять исходный SKU, аккаунт, base, сумму вычета, итог, валюту, timestamp, версию snapshot.
- При утверждении и перед **первой фактической отправкой** заново читать `standardPrice.amount` старого SKU; изменение базы сбрасывает approval.
- Сохранять immutable payload для отправки. Повторная попытка не должна ещё раз уменьшить уже пересчитанную цену.
- После успешной разрешённой операции проверять стандартную цену **нового** SKU в OTTO.

**Пример изменения цены:** OTTO было 100 €, стало 110 €: JV `90 → 100 €`, XL `85 → 95 €` (пересчёт отдельно по аккаунтам).

### 6.4. Жизненный цикл

```text
IMPORTED → VALIDATING_SOURCE → CHECKING_OTTO_STATUS
→ FETCHING_OTTO_STANDARD_PRICE → ELIGIBILITY_REVIEW
→ READY_FOR_PREPARATION → GTIN_RESERVED → CONTENT_PREPARED
→ VALIDATED → READY_FOR_APPROVAL → APPROVED → QUEUED
→ SUBMITTED_TO_OTTO → OTTO_PROCESSING → OTTO_MARKETPLACE_CHECK
→ ONLINE_CONFIRMED
```

Возможные блокировки/ошибки: `NEEDS_INPUT`, `PRICE_UNAVAILABLE`, `PRICE_REVIEW_REQUIRED`, `PRICE_CHANGED_REAPPROVAL_REQUIRED`, `GTIN_REVIEW_REQUIRED`, `BLOCKED_BY_OTTO`, `VALIDATION_FAILED`, `SUBMISSION_FAILED`, `MARKETPLACE_RESTRICTED`, `PRICE_SYNC_FAILED`, `CANCELLED`.

Проверять отдельно `activeStatus` и `marketplaceStatus`. `202 Accepted`, успешный update-task, MOIN или `active=true` **не равны** `ONLINE_CONFIRMED`. Для успешного статуса нужна независимая проверка состояния и цены в OTTO.

### 6.5. Ограничения OTTO/GS1

- GTIN/EAN предназначен для идентификации торговой единицы; само изменение названия или цены не является основанием для выдачи нового GTIN неизменённому физическому товару.
- Перед production publish проверить правомерность использования новых GTIN и разрешённость повторного размещения товара после 3/12M.
- Эксперимент с тем же `productReference` — только для действительно допустимых вариаций и после подтверждения со стороны OTTO. Он не должен служить механизмом обхода ограничений.
- Предусмотреть режим read-only / dry-run даже если production-публикация юридически или технически не разрешена.
- `restart_publish_enabled=false` по умолчанию; включение требует подтверждённого business gate и отдельного разрешения пользователя.
